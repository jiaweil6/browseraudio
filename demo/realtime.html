Feature · Real-time

Real-time synthesis, block by block

A sound card doesn't take a whole song at once: it keeps asking for the next short block of samples, and a callback must fill each one in time. Here the browser is the sound card and your NumPy callback answers it — live, while you play.

This page runs a real in-browser Python kernel (thebe + Pyodide) with the actual browseraudio package — so the cells below are the genuine API, just like JupyterLite / thebe. The cells are editable; the first Run downloads the runtime (~25 MB), so give it a moment. Reload to reset.

01

A callback with state

The control (the pitch) is read once per block, and the phase is state, carried from one block to the next so the sine never jumps. With no key held the pitch is None and the block stays silent. Run the cell, press ▶ Start, click the keyboard, then hold keys: A S D F G H J K L ; are the white keys, W E T Y U O P the black keys, Z / X shift the octave.

python
import numpy as np
from browseraudio import stream

class Sinusoid:
    def __init__(self):
        self.pitch, self.phase = None, 0.0  # None: no key held

    def callback(self, block):           # block: (B, 1), with .sample_rate
        if self.pitch is None:              # read the control once
            return                          # the block stays silent
        f = 440 * 2 ** ((self.pitch - 69) / 12)
        B = len(block)
        dphase = 2 * np.pi * f / block.sample_rate
        block[:] = 0.3 * np.sin(self.phase + dphase * np.arange(B))[:, np.newaxis]
        self.phase = (self.phase + dphase * B) % (2 * np.pi)

synth = Sinusoid()

def on_note(midi, on):
    if on:
        synth.pitch = midi                  # a new key: glide, keep the phase
    elif midi == synth.pitch:               # the sounding key was released
        synth.pitch = None

s = stream(synth.callback, sample_rate=44100, block_size=512, on_note=on_note)

Python never keeps time here: the page's audio thread plays a short queue of blocks and asks the kernel for the next one as each finishes. So a key press is heard after the queued audio plus one round trip to the kernel — the widget shows both, live.

02

Block size: time budget vs. latency

Every block must be ready before the one ahead of it finishes playing. Small blocks mean many callback calls per second — watch % of budget climb at B = 1. Big blocks are cheap, but your key presses wait behind them — at B = 16384 notes arrive late and quick ones are skipped entirely. Change the size, run the cell, and press ▶ Start again.

python
s.block_size = 16384     # try 1, 64, 512, 16384 — then ▶ Start
03

A live wavetable synth

Read one cycle of a waveform at a speed set by the pitch, with linear interpolation. Releasing the key silences the block and resets the read position, so the next note starts at the top of the table; switching keys while one is held keeps the phase.

python
s.stop()                          # stop the stream above

M = 2048
m = np.arange(M)
table = sum(a * np.sin(2 * np.pi * k * m / M) for k, a in enumerate([1, 0.5, 0.5, 0.25], 1))

class Wavetable:
    def __init__(self):
        self.pitch, self.pos = None, 0.0  # None: no key held

    def callback(self, block):
        if self.pitch is None:
            self.pos = 0.0              # the block stays silent
            return
        f = 440 * 2 ** ((self.pitch - 69) / 12)
        step = f * M / block.sample_rate
        p = (self.pos + step * np.arange(len(block))) % M
        i = p.astype(int)
        a = p - i
        block[:, 0] = 0.15 * ((1 - a) * table[i] + a * table[(i + 1) % M])
        self.pos = (self.pos + step * len(block)) % M

wt = Wavetable()

def on_note(midi, on):
    if on:
        wt.pitch = midi
    elif midi == wt.pitch:             # the held key was released
        wt.pitch = None

s = stream(wt.callback, sample_rate=44100, block_size=512, on_note=on_note)
04

Genie mode on a stream

The same callback, played in genie mode: eight buttons (1–8 or A S D F J K L ;), and a neural network picks which piano key each press becomes. Your on_note receives the genie's notes, so nothing else changes. You can also flip the Keys | Genie switch on any stream above.

python
s.stop()
s = stream(wt.callback, sample_rate=44100, block_size=512, on_note=on_note,
           input="genie", genie_range=(48, 84))   # C3 to C6

Genie mode is Piano Genie — Chris Donahue, Ian Simon & Sander Dieleman, Piano Genie, IUI 2019 (arXiv:1810.03226) — running the trained model published by Magenta. Please cite it if you use genie mode in your work.

05

sounddevice code, and any widget as a control

Code written for sounddevice.OutputStream runs too: its callback(outdata, frames, time, status) is pulled the same way. Any widget can steer it — its value reaches the kernel between blocks. Moving the slider multiplies the tone by a ramp from the previous level to the new one (de-zippering), so the volume glides instead of clicking.

python
import ipywidgets as widgets
import browseraudio.sounddevice as sd

s.stop()
level = widgets.FloatSlider(value=0.5, min=0, max=1, step=0.1, description="level")
phase, previous = 0.0, level.value

def callback(outdata, frames, time, status):
    global phase, previous
    step = 2 * np.pi * 220 / 44100
    tone = np.sin(phase + step * np.arange(frames))
    phase = (phase + step * frames) % (2 * np.pi)
    ramp = np.linspace(previous, level.value, frames, endpoint=False)
    previous = level.value
    outdata[:] = 0.3 * (ramp * tone)[:, np.newaxis]

out = sd.OutputStream(samplerate=44100, blocksize=512, channels=1, callback=callback)
out.start()
level

Blocks are made only while no cell is running, so keep long computations out of the way while a stream plays — a busy kernel is heard as dropouts.
